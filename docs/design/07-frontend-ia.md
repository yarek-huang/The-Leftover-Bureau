# 07 · 前端信息架构

> 来源决策：006 Vue3+Vite SPA、012 录入三通道、002 拍照为主入口、003 聚合视图默认。

## 信息架构（IA）

```
顶部导航：[首页聚合] [我的冰箱] [食谱库] [我的食谱] [卷宗]   右上：[+ 录入] [👤]
```

### 首页聚合（默认着陆）
- **顶部红色通缉令面板**：跨冰箱汇总 3 天内到期食材，按到期远近排序，每条带「极速清场」快捷按钮。
- **下方聚合食材列表**：全部活跃冰箱食材汇总，可按单冰箱筛选（顶部 segmented control）。
- 筛选状态联动推荐范围（单冰箱推 vs 跨冰箱合推）。

### 我的冰箱
- 冰箱卡片列表（含归档的，归档卡片置灰带"恢复"按钮）。
- 点卡片进单冰箱详情：食材列表 + 成员 + 邀请码 + 历史（FridgeEvent 留痕）。

### 食谱库（公开）
- approved 食谱浏览，按荤素/难度筛选（不设标签体系）。
- 每个食谱卡片：主料预览 + 步骤摘要 + 「用这个做」按钮（带去极速清场匹配）。

### 我的食谱
- 我建的食谱列表（含 status 状态徽章 + rejected 理由）。
- 「新建食谱」入口 → 表单 → submit_for_review 选择。

### 卷宗
- 做饭历史列表，每条：日期 + 评分 + 用了哪些食材 + 关联食谱（有则）。
- 「记录卷宗」入口 → 手动归档。

## 录入入口（+ 按钮）

点顶部「+ 录入」→ 弹底部 sheet 双通道选择：
1. **拍照**（主入口，012）：拍/上传 → 识别 → 逐条确认 → 入库。
2. **文字**：批量多行表单一次提交。

语音录入延后（002）。

## 关键页面流程

### 拍照录入流
```
+ 录入 → 拍照 → 等待识别(loading) → 识别结果列表(每条可改/删/补 quantity+zone+state+expiry)
  → 全部确认 → 入库成功 → 回首页(红色通缉令刷新)
识别失败 → 退回文字表单(预填已识别部分)
```

### 极速清场流
```
红色通缉令面板「极速清场」 → loading(同步 ≤30s) → 套餐结果卡(主料全/差一附补购单)
  → 看食谱详情 → 做 → 记卷宗
LLM 失败 → 报错「推荐暂不可用」
```

### 饕餮盛宴流
```
首页「给我推荐晚餐」 → 异步任务(task_id) → 轮询 → 套餐结果
  → 看食谱详情 → 做 → 记卷宗
```

### 审核流（admin）
```
admin 顶导航多一项「审核」→ 待审列表 → 食谱全貌预览 → 通过/驳回(填理由)
```

## 移动端响应式（012）

- V1 两通道（拍照 + 文字）全程移动端可用，拍照为主入口。
- 底部 sheet、卡片堆叠、单列布局；桌面端横向扩双列。
- 不做原生 App，PWA 可选（V1 不强求）。

## 状态徽章

| 食谱状态 | 徽章颜色 |
|---|---|
| private | 灰 |
| pending | 黄 |
| approved | 绿 |
| rejected | 红（带理由 tooltip） |

## 验收用例

1. **临期五花肉**：首页着陆 → 红色通缉令面板见五花肉（2 天）→ 点「极速清场」→ 套餐结果。
2. **半颗卷心菜**：聚合食材列表见"半个卷心菜"→ 顶部「给我推荐晚餐」→ 盛宴匹配卷心菜食谱。
3. **不明剩菜盒**：+ 录入 → 拍照识别返回"剩菜盒"→ 改成"红烧肉剩菜"+state=leftover → 入库 → 首页推荐带剩菜改造方案。
4. **审核**：admin 点「审核」→ 妻子的"番茄炒蛋"待审 → 预览 → 通过 → 食谱库立即可见。
