# 拍照识别技术路线调研（票：拍照识别技术路线）

> 调研日期：2026-08。论断来源见各节链接。用途：为「食材录入三通道交互」（012）与设计文档拍板 V1 识别路线。

## 结论速览

| 路线 | V1 适配度 | 依据 |
|---|---|---|
| **多模态 LLM（GLM-4.6V-Flash 免费档）** | ✅ 推荐 | 零数据/零训练/零调用成本；中文食材名直接识别；官方支持结构化输出（json_object）与多目标计数；天然契合「拍照→识别→人工确认→入库」（002 已定流程） |
| YOLOv8 自建 | ❌ V1 不建议 | 无覆盖中国家庭生鲜食材的公开数据集（见下）；需自采自标自训，成本全在数据不在模型 |
| CLIP 开放词汇零样本 | ⚠️ 备选 | 模型现成（openai/clip 系列，HF 下载量千万级），但英文为中心、中文食材名需翻译桥接，冰箱杂乱场景精度未验证 |
| 现成食物识别 API | ⚠️ 未验证 | 百度/腾讯文档页 JS 渲染无法核实现状；且多为「菜品识别」而非「生鲜食材识别」，与需求错位 |

## 1. 数据集事实（YOLO 路线的地基不存在）

- **Food-101**：101 类全是**菜品**（apple_pie、baby_back_ribs、bibimbap…），10 万张图，众包，许可证 unknown（[HF ethz/food101](https://huggingface.co/datasets/ethz/food101)，README 已核实）。菜品 ≠ 生鲜食材，对"冰箱里的半颗卷心菜"无能为力。
- **冰箱场景数据集**：HF 搜索 fridge 相关数据集仅小型社区数据集（下载量 < 100），无可用的大规模冰箱内容识别集（[HF API 检索](https://huggingface.co/api/datasets?search=fridge)，2026-08 核实）。
- **蔬果类数据集**：HF 上仅有小型社区集（如 henningheyen/LVIS_Fruits_And_Vegetables，547 下载）——远不覆盖中国家庭常见食材（冬瓜、五花肉、嫩豆腐…），且不含"冰箱杂乱摆放、部分遮挡、包装混杂"的现实分布。
- ChineseFoodNet（中式菜品 208 类）GitHub 原址已 404，可用性存疑；且同样面向菜品。

**判定**：README 写的 YOLOv8 路线隐含"有数据可训"的假设，实际不成立。自建需自采数据 + 人工标注（估计每类数百张才能稳定），对家庭项目是数月级杂活。

## 2. 多模态 LLM 路线（推荐）

- **GLM-4.6V 系列**（[官方文档](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-4.6v)）：
  - 三档：GLM-4.6V（106B 高性能）/ GLM-4.6V-FlashX（9B 轻量高速）/ **GLM-4.6V-Flash（完全免费，官方原文）**。
  - 官方推荐场景直接命中本项目：**物体检测与计数**（"识别并定位一个或多个特定目标…对指定类别进行高精度计数"）、**商品属性识别**（品目/材质多维属性）；支持 base64 直传、json_object 结构化输出（007 已核实）、思考模式可开关。
  - 官方基准声明：9B Flash 整体超过 Qwen3-VL-8B（官方自述，非独立验证）。
  - 128K 上下文，输入图像/视频/文件。
- **通义 Qwen3.5-omni-plus**（007 已核实）：国内直连多模态备选，付费。
- **OpenAI GPT-5.6 / Claude**：能力最强但需代理，作有代理环境的对照档。

**已知局限**（诚实记录）：VLM 对**数量/份量**的估计不稳定（"大概 200g"不可靠）；冰箱内遮挡、包装食材识别有失败率。缓解：002 已定「识别结果必经人工确认修正」，数量默认留给用户填，识别只负责"有什么"。

## 3. 中间路线

- **CLIP 零样本**：openai/clip-vit-base/large 现成（HF 下载 2 万+ / 629 万），可对候选食材名列表做相似度匹配；但英文为中心（中文食材需 CN-CLIP 或翻译），冰箱实拍分布上无基准数据，效果未知。仅当 LLM 路线延迟/成本不可接受时再评估。
- **现成识别 API**（百度菜品识别/腾讯图像识别）：文档页 JS 渲染，2026-08 未能核实可用性与价格；且定位是"菜品"识别，与生鲜食材需求错位。不作为 V1 依赖。

## 4. 对 V1 的建议（供 012 与设计文档采纳，非最终决策）

1. 识别走 provider 抽象层的 `vision` 槽位（007 建议已预留），默认 GLM-4.6V-Flash，配置可切换 Qwen3.5-omni-plus / GPT-5.6。
2. 识别 prompt 输出结构化 JSON：`[{name, quantity_guess?, confidence, bbox?}]`，quantity 仅作参考不作真值。
3. 前端人工确认页是产品质量的关键闸门（002 已定），识别失败路径 = 退回文字录入。
4. YOLO 自建不在 V1 路线；若未来识别质量成为瓶颈，再评估"用户确认数据回流 → 微调小模型"的飞轮（那是 V2+ 的事）。

## 附：未核实项

- GLM-4.6V-Flash 免费档的并发/速率限制（官方未在文档页写明，接入时实测）。
- 百度/腾讯识别 API 现状（页面 JS 渲染抓取不到）。
