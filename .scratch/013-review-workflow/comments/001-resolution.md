# Resolution

## 审核工作流（Yk 定案，2026-08）

### 食谱状态机

```
private → pending → approved（全平台公开）
                 ↘ rejected（带拒绝理由）→ 可修改后重提 → pending
```
- 被拒**可改后重提**（rejected → pending），驳回必填理由字段。
- admin 直接创建的食谱**跳过队列**直接 approved（admin 自己建的种子/起步食谱不必自审）。

### admin 特权范围

- 审核 + 下架已公开食谱 + 编辑种子食谱 + 重置用户密码（010 已定 admin 可转让/多任）。

### 种子食谱（推翻 002 的 AI 批量生成）

- **V1 不做 AI 批量生成种子**——Yk 上线后通过 admin 直接创建入口手动批量添加（直接 approved，跳过队列）。002 的"AI 批量生成种子库"决议据此修订。

### V1 食谱库起步态（库空降级）

- **空库起步**：库空或无匹配时，极速清场**降级为 LLM 现场生成"出清方案"**（与饕餮盛宴的生成路径合并，区别只在 prompt 目标——清冰箱 vs 高配）。据此修订 005 的"极速清场=库内检索"假设：库内有匹配时走检索，否则降级生成。

### 审核后台（极简）

- 待审列表 + 食谱全貌预览 + 通过 / 驳回（驳回填理由）按钮，**仅此**。不做批量审核工具。

### 提交者反馈

- **站内标记**：提交者个人页看到自己食谱的状态 + 理由，无推送通知。

### 审核标准

- **不成文**，admin 个人判断。

## 域词汇（已同步 CONTEXT.md）

RecipeStatus（private/pending/approved/rejected）、Review Queue（待审队列）、Admin Direct-Create（admin 建食谱跳过队列）。
