# Resolution

## 食材条目模型（Yk 定案，2026-08）

### 实体：单层 StockItem（无字典层）

- **一层建模**：每个库存条目自带名字（自由文本，"番茄""五花肉""半份红烧肉"皆可），**不做食材字典**。
- 推翻两处前置假设，以此为准确认过 Yk：
  - 推翻 002 的"预置食材默认保质期字典，录入自动带出"→ **保质期完全手填**（不填则无到期日，无高亮）。
  - Q6"纯自由输入，不做字典"与 Q5 引用字典天数的矛盾，按"彻底无字典"消解。

### 数量：纯文本

- 数量为**自由文本**（"大概半个""约 200g""两袋"），不做数值+单位结构化，不做换算。

### 位置与状态

- **位置三区**：冷冻 / 冷藏 / 常温，录入必选，默认冷藏。
- **状态字段**：生鲜 / 熟食 / 剩菜。熟食剩菜保质期短、推荐优先级高（喂给推荐作信号）。

### 保质期

- 只记**到期日**（手填、可跳过）。"红色通缉令"= 3 天内到期高亮排序，过期未删持续高亮（已过期待办）。

### 生命周期与留痕

- **条目也留痕**：删除/消耗均记入冰箱历史（谁、何时、对哪条、动作），与 003 成员留痕署名精神对齐。
- 卷宗归档（002）时快照所耗食材名目——历史双轨：条目级操作历史 + 卷宗级做饭记录。

### 对识别录入的影响（联动 008/012）

- 拍照识别输出结构仍有效（识别"有什么"），但**数量建议字段降级为纯参考**：入库数量是自由文本，用户口头描述填入。

## 域词汇（已同步 CONTEXT.md）

StockItem（库存条目：名字/数量文本/位置/状态/到期日）、StorageZone（冷冻/冷藏/常温）、ItemState（生鲜/熟食/剩菜）、Fridge History（冰箱操作历史，条目级留痕）、Expiry Alert 红色通缉令（3 天内到期高亮）。

## 对地图的影响

- "识别输出带 quantity_guess"建议作废，识别只报名称+置信度，数量由人工确认页自由文本输入。
- 005 食谱与推荐模型获得输入：推荐匹配面对的是自由文本食材名（无字典归一），匹配策略必须容忍字面差异（LLM 语义匹配而非精确 ID 匹配）——写进 005 的已知约束。
